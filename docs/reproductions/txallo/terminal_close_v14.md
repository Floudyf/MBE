# TxAllo v14 — postprocessing evidence closure

Scope: TxAllo observations **only**. This is not a TxAllo performance or PBFT change.

## What is produced

1. `aggregate/txallo_evidence_summary.json`: existing v1.2 audit, generated by the metric extractor.
2. `aggregate/txallo_terminal_breakdown.json`: new offline audit, correlating source-block epochs, client placement, and same-node lifecycle stages.
3. `artifact_catalog.json`: incrementally refreshed (new small files only; no rehash of raw WAL/DB) after metric extraction and terminal audit, **before** formal child cold archive, containing hashes and locations for (1) and (2).

Both aggregate summaries are retained in the online cold-archive shell; their source files remain in the full verified archive. No additional execution-gating expected-artifact requirement is introduced.

## Measurement contract

- Source epoch = `(raw_block_num - first_block_num) // a_epoch_blocks` from aligned TxAllo sidecar, not routing_epoch or replay wall clock.
- Client `commit_wait_ns`: elapsed time measured by the client monotonic timer, **not** the sum of transaction-stage durations.
- Same-node durations may use `received -> admitted -> proposed -> quorum_committed -> durable_committed` from that node's JSONL lifecycle log. Percentiles interpolate the available same-node samples; missing samples are `null`, never zero.
- Cross-node absolute timestamps **cannot** be subtracted unless independent clock synchronization uncertainty evidence exists. This audit does not assert that evidence, so cross-node latency and global critical path are always `null`.
- Stateful sourcefinalize is a separate protocol stage, but a unique end-to-end duration is not claimed without a complete comparable-clock chain.
- PBFT replication duplicates transaction events, so samples are stage-level observations and **not** unique logical transaction latency observations. The report gives per-stage distinct logical counts and same-node pair sample counts.
- Last partial source epoch does not feed dynamic allocation; it may have placements but lacks a close barrier entry.
- Error/missing observations are diagnostic; formal eligibility remains governed by the existing runtime artifact contract and correctness oracles.

## Paper usage

Do **not** add different nodes' per-stage times to explain 763s or 345s epoch waits. The validated statement is that client waits dominate per-epoch barrier time; micro causes remain limited by available time-aligned evidence. Use a clock-synchronized profiler in a separate future diagnostic campaign if exact global decomposition is required.
