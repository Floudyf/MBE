# Porygon reproduction deviations — current MBE adaptation

1. **Consensus adaptation.** The paper's ordering consensus is not reproduced as BA★. MBE's shared `pbft_style_consensus` remains unchanged so all baselines retain the same consensus layer.
2. **Single physical ordering domain.** `topology.shards` controls logical Porygon ESC/StateOwner partitions; all validators still share one physical `porygon-global` PBFT ordering domain. Increasing the frontend shard count never multiplies PBFT domains.
3. **Committee selection adaptation.** The EC/ESC lifecycle and rotation are represented, but MBE uses deterministic sortition over the fixed validator population rather than claiming exact paper VRF selection.
4. **Co-located Storage Roles.** MBE does not add separate physical Storage Node processes. Existing nodes carry fixed Storage Role identities in addition to PBFT/dynamic ESC roles. State and full TransactionBlock persistence are restricted by those fixed roles, and remote execution receives only verified signed-access projections.
5. **Witness deployment adaptation.** Witness voting is real and authenticated, but Witness members reuse the existing validator identities rather than a separately provisioned physical node population. The effective threshold is fault-bound (`f+1` minimum), not merely metadata.
6. **Pipeline adaptation.** PBFT ordering heights stay sequential. Porygon Execution/Materialization of earlier heights may overlap later Ordering and Cross-Batch Witness; speedup is claimed only from measured runtime interval overlap, never from logical slot labels alone.
7. **Generic smart-contract StateOwner mapping.** MBE state keys are reduced to stable account/object owner identities by the Porygon sharding plugin so related fields remain together. This is an MBE data-model adapter, not a claim that the paper used these exact key formats.
8. **Declared-access truth.** The paper's known transaction state is represented by the signed MBE runtime `AccessList`. This is admitted before mempool entry; scheduler overlays and MetaTrack version metadata are excluded.
9. **ESC result authentication.** ESC batch attestations reuse each validator's existing PBFT Ed25519 identity. Porygon execution threshold `Te=f+1` is distinct from the strict-majority root threshold used by Multi-Shard Update.
10. **Fault recovery boundary.** Normal ITx/CTx protocol rounds are represented, but exact future-same-shard ESC retry followed by proposal-carried rollback is not yet claimed. The current implementation must fail closed rather than substituting the retired generic rollback RPC path.
